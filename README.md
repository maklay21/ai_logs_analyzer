# AI Logs Analyzer

AI Logs Analyzer — MVP для автоматического разбора логов и наблюдения за ресурсами приложения. После запуска веб-приложения фоновый оркестратор сам проверяет настроенные папки, сохраняет события и обновляет отчёт. При выборе режима OpenAI или Anthropic он также передаёт модели контекст и ограниченный набор MCP-инструментов для расследования. Режим local работает без внешней модели.

## Что делает приложение

- Читает файлы логов из подключённых папок и приводит строки к общему формату событий.
- Считает события по уровням, объединяет повторяющиеся ошибки и строит ориентировочный граф связей по общему trace/request ID.
- Хранит источники, разобранные события, отчёты и метрики в отдельной SQLite-БД, общей для API и MCP. Основная БД приложения остаётся отдельной.
- Самостоятельно запускает проверку при старте и повторяет её через заданный интервал.
- Собирает метрики CPU и памяти хоста и API, а при настройке — выбранного Docker-контейнера.
- Показывает источники, события, отчёты и метрики в веб-панели.


## API приложения

API приложения AI Logs Analyzer написан на FastAPI. Он предоставляет API-контракты для веб-панели (React): управление источниками логов, просмотр событий и отчётов, получение состояния агента и истории метрик. Интерактивная документация API доступна по адресу `/docs` при локальном запуске.

При старте FastAPI подготавливает схемы баз данных и запускает фоновые задачи: оркестратор периодического анализа логов и сборщик метрик ресурсов. Оркестратор общается с MCP-сервером по stdio, а сервер сканирует разрешённые папки и сохраняет источники, разобранные события и отчёты в общей аналитической SQLite-БД. React-клиент обращается к REST API FastAPI и получает от него данные для панели.

## Как устроен ИИ-анализ

    Папка с логами
          │
          ▼
    Фоновый оркестратор FastAPI
          │ вызывает инструменты через MCP по stdio
          ▼
    MCP-сервер приложения ── читает файлы и работает с аналитической SQLite
          │                       ▲
          │                       └── API читает те же источники, события, отчёты и метрики
          ├── AI_PROVIDER=local ── отчёт по правилам Python, без модели
          │
          └── OpenAI / Anthropic ── модель запрашивает разрешённые MCP-инструменты
                                          │
                                          ▼
                                 итоговый отчёт в базе данных
                                          │
                                          ▼
                                      React-панель

При запуске FastAPI создаёт фоновые задачи: оркестратор анализа и сборщик метрик. Оркестратор запускает MCP-сервер как дочерний процесс и общается с ним по stdio. MCP здесь — внутренний протокол между оркестратором и инструментами приложения. Он используется независимо от выбора OpenAI, Anthropic или local. Основная БД задаётся через DATABASE_URL. Отдельная SQLite-БД из MCP_DATABASE_URL содержит источники, разобранные события, отчёты и метрики; API и MCP используют её совместно. В Compose файл SQLite находится в постоянном томе mcp_data.

В каждом цикле приложение регистрирует настроенные источники, сканирует их и сравнивает подпись результата с предыдущим циклом. Если содержимое не изменилось, новый отчёт не создаётся. Если изменилось, local формирует отчёт правилами Python. При выборе модели оркестратор передаёт ей результат сканирования и выполняет разрешённые запросы контекста через MCP. Отчёт сохраняется в базе и отображается в панели.

## Режимы анализа

| AI_PROVIDER | Работа | Нужен ключ |
| --- | --- | --- |
| local | Автосканирование и базовый отчёт: уровни, повторяющиеся ошибки, связи по trace ID. Модель не вызывается. | Нет |
| openai | Расследование через OpenAI Responses API с разрешёнными вызовами инструментов. | OPENAI_API_KEY |
| anthropic | Расследование через Anthropic Messages API с разрешёнными вызовами инструментов. | ANTHROPIC_API_KEY |

Провайдер и ключи задаются на сервере в .env; браузер их не получает. При использовании облачной модели ей передаются сообщения из логов и контекст расследования. Убедитесь, что эти данные можно передавать выбранному сервису.

## MCP в этом проекте

MCP (Model Context Protocol) - это протокол, которым оркестратор приложения вызывает инструменты, необходимые автоматическому анализу. Для режимов OpenAI и Anthropic модель может попросить оркестратор выполнить разрешённый инструмент; оркестратор обращается к MCP-серверу и возвращает результат модели. В режиме local сервер MCP также регистрирует источники и сканирует логи, но модель и цикл вызова инструментов не запускаются.

Инструменты MCP:

- register_configured_sources и scan_log_source — регистрация и сканирование; вызываются оркестратором;
- list_log_sources — список источников;
- search_log_events — поиск среди сохранённых событий;
- get_latest_analysis — чтение предыдущего отчёта;
- get_resource_history — чтение истории метрик.

Во время автоматического расследования модели доступны только инструменты чтения событий, отчётов и метрик. Произвольный доступ к файловой системе, shell и Docker API не предоставляется. Число шагов модели ограничено настройкой AGENT_MAX_STEPS.

Этот же MCP-сервер можно дополнительно подключить к внешнему MCP-клиенту, например Claude Code, чтобы вручную просматривать данные. Это необязательная интеграция: приложение и автоматический агент работают без Claude Code.

## Запуск через Docker Compose

Требования: Docker Compose v2 и папка с логами.

    cp .env.example .env

В .env настройте:

- POSTGRES_PASSWORD — пароль PostgreSQL.
- LOGS_PATH — путь к папке логов на хосте. По умолчанию используется ./sample_logs.
- LOG_ALLOWED_ROOTS — разрешённые пути внутри контейнера; по умолчанию /logs.
- AUTO_LOG_SOURCE_PATHS — источники внутри контейнера для автоматической регистрации; по умолчанию /logs.
- AI_PROVIDER — local, openai или anthropic. В .env.example выбран anthropic; для модели добавьте соответствующий API-ключ.
- AGENT_POLL_SECONDS — период проверки логов, по умолчанию 60 секунд.
- TARGET_CONTAINER — имя Docker-контейнера, если нужны его метрики.

Пути AUTO_LOG_SOURCE_PATHS должны существовать внутри контейнера и находиться в LOG_ALLOWED_ROOTS. Несколько папок указываются через запятую. Не задавайте одновременно родительскую папку и её вложенную папку.

    docker compose up --build -d

Панель будет доступна по адресу http://localhost:8080. Агент начинает сканирование сам; кнопка запуска не требуется. Дополнительную разрешённую папку можно добавить из панели, агент подхватит её в следующем цикле.

    docker compose logs -f api
    docker compose logs -f frontend
    docker compose down

## Локальный запуск

Необходим Python версии, указанной в pyproject.toml.

    python -m venv .venv
    source .venv/bin/activate
    python -m pip install -e '.[dev]'

Пример запуска с логами из проекта и SQLite:

    export DATABASE_URL='sqlite+pysqlite:///./ai_logs_analyzer.db'
    export MCP_DATABASE_URL='sqlite+pysqlite:///./ai_logs_analyzer_mcp.db'
    export LOG_ALLOWED_ROOTS="$PWD/sample_logs"
    export AUTO_LOG_SOURCE_PATHS="$PWD/sample_logs"
    export AI_PROVIDER=local
    uvicorn app.main:app --reload

API доступно по адресу http://localhost:8000, документация — http://localhost:8000/docs. Локально основная БД задаётся через DATABASE_URL, а аналитические данные API и дочернего MCP-сервера — отдельным файлом из MCP_DATABASE_URL. В Compose основная БД — PostgreSQL, аналитические данные хранятся в SQLite в постоянном томе.

## Метрики ресурсов

Сборщик с интервалом RESOURCE_POLL_SECONDS записывает CPU и память хоста и процесса API, использование корневого диска и, если задан TARGET_CONTAINER, метрики выбранного контейнера. Compose подключает Docker socket для чтения статистики. Доступ к нему чувствителен: запускайте панель на доверенной машине и не выставляйте её в публичную сеть без защиты. Если метрики контейнера не нужны, удалите подключение сокета из Compose.

## Форматы логов и ограничения

Поддерживаются .log, .txt, .out и .jsonl. Для JSON распознаются распространённые поля времени (timestamp, time, @timestamp), уровня (level, severity), логгера (logger, name), сообщения (message, msg) и идентификатора трассировки (trace_id, request_id). Текстовые строки разбираются эвристически.

Каждый цикл перечитывает файлы и заменяет сохранённые события данного источника результатом сканирования. По умолчанию обрабатывается до 500 файлов и 50 000 непустых строк на источник; лимиты настраиваются через MAX_LOG_FILES и MAX_LOG_LINES. Инкрементальное чтение пока не реализовано. Граф строится по порядку логгеров в записях с общим trace/request ID и является ориентиром, а не полной картой вызовов.

Запускайте одну реплику API: координация фонового агента между репликами пока не реализована. Аутентификация и очередь задач не входят в MVP.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| DATABASE_URL | SQLite-файл локально; PostgreSQL в Compose | Основная БД приложения |
| MCP_DATABASE_URL | SQLite-файл локально; /data/ai_logs_analyzer_mcp.db в Compose | SQLite для источников, событий, отчётов и метрик; Compose сохраняет её в томе mcp_data |
| LOG_ALLOWED_ROOTS | /logs | Разрешённые корни логов |
| AUTO_LOG_SOURCE_PATHS | /logs | Автоматически регистрируемые папки |
| AI_PROVIDER | local в коде; anthropic в .env.example | Локальные правила или провайдер модели |
| OPENAI_API_KEY, OPENAI_MODEL | ключ пуст; gpt-5-mini | Доступ и модель OpenAI |
| ANTHROPIC_API_KEY, ANTHROPIC_MODEL | ключ пуст; claude-sonnet-5 | Доступ и модель Anthropic |
| AGENT_POLL_SECONDS | 60 | Интервал проверки, минимум 15 секунд |
| AGENT_MAX_STEPS | 8 | Максимум шагов модели на расследование |
| RESOURCE_POLL_SECONDS | 15 | Интервал сбора метрик |
| TARGET_CONTAINER | пусто | Имя контейнера для Docker-метрик |
| MAX_LOG_FILES | 500 | Максимум файлов на источник |
| MAX_LOG_LINES | 50000 | Максимум непустых строк на источник |
